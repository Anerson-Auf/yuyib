# Нативный UI

> **Статус:** Experimental  
> **Crate / module:** `yuyib::ui`, `yuyib::ui_render`, `yuyib::ui_text`

`yuyib-ui` — нативное дерево интерфейса, независимое от конкретного рендерера.
Оно не требует HTML/JSX и не навязывает внешний вид режима разработки:
приложение создаёт типизированное дерево с постоянными `WidgetId`, палитрой и
правилами размеров. Позже ту же смысловую раскладку смогут использовать WGPU
и системный мост доступности.

`UiBuilder`/`ChildrenBuilder` создают дерево; `layout` строит повторяемый
`UiLayout`; `handle_input` превращает нажатия мыши в `UiResponse`. Есть
`Row`, `Column`, `Absolute` и размеры `Auto`/точный `Points`/`Fill`.
При попадании мыши верхним считается последний соседний элемент. Сейчас
интерактивна только `Button`: клик происходит, если нажатие и отпускание были
на одной кнопке.

`handle_keyboard_input` добавляет переходы `Tab`/`ShiftTab`, активацию
`Enter`/`Space` и `UiInputState::focused`. Порядок фокуса соответствует
порядку рисования в глубину и зацикливается. Отключённые кнопки остаются в
раскладке и на экране, но не получают фокус и мышь. Адаптеры ввода платформы
переводят физические клавиши в `KeyboardInput`, не зная устройства дерева.

Полный API: [нативный UI](../api/yuyib_ui/index.html).

`yuyib::ui_render` — первый WGPU-мост: `extract_draw_list` выдаёт
повторяемый список прямоугольников, а `UiRenderer` записывает один цветной
проход поверх существующего `RenderFrame`. Порядок дерева сохраняется.
Низкоуровневый пользователь сам согласует область рендера и DPI.

## Живая галерея

```text
cargo run -p yuyib --example native_ui_gallery
```

Пример показывает весь текущий набор готовых элементов: `Container`, `Label`,
`Button`; три вида раскладки и размеры `Auto`, `Points`, `Fill`. Кнопки можно
нажимать мышью и клавиатурой; полученные действия печатаются в терминал.
Такой список отражает текущий scope: несуществующие пока текстовые поля, флажки,
списки и прокрутка пример не имитирует.

## Текст в готовом Application UI

`ApplicationUi::with_text` — готовый путь для подписей и кнопок. Он
принимает один явно заданный шрифт, измеряет содержимое до раскладки и собирает
все подписи кадра в один текстовый GPU-проход. Поэтому `Auto` учитывает текст
и внутренние отступы, а обычное окно с интерфейсом не делает отдельный GPU-вызов
на каждую букву или кнопку. В готовом пути текст рисуется поверх фонов UI;
нестандартный порядок проходов остаётся низкоуровневой задачей.

```rust,no_run
use yuyib::{
    app::{ApplicationUi, NativeUiTextConfig},
    ui::{LayoutKind, UiBuilder, Widget, WidgetId},
    ui_text::FontSource,
};

let tree = UiBuilder::new(WidgetId::from_key("root"), LayoutKind::Column)
    .child(Widget::label(WidgetId::from_key("title"), "Загрузка"))
    .child(Widget::button(WidgetId::from_key("cancel"), "Отмена"))
    .build()?;
let ui = ApplicationUi::new(tree).with_text(
    NativeUiTextConfig::new(FontSource::file("assets/fonts/Inter-Regular.ttf")),
)?;
# Ok::<(), Box<dyn std::error::Error>>(())
```

Шрифт не подбирается из Windows автоматически. Для готовой игры положите его
в ресурсы приложения и используйте `FontSource::bytes`; путь в примере удобен только для
разработки. Настройки размера, атласа и лимитов GPU находятся в одном
`NativeUiTextConfig`. Низкоуровневые `TextEngine`, `TextRasterizer` и
`TextGlyphRenderer` остаются доступны, когда нужен собственный порядок
проходов или нестандартная графика.

## Limits & Caveats

Базовое дерево намеренно не владеет окном Winit, мостом доступности,
прокруткой, отсечением области, анимациями, WebView/HTML/CSS или реактивным состоянием.
Обычный `layout` сохраняет прежнее простое правило: `Auto`
использует `WidgetStyle::min_size`. Для собственного текста, иконок или другой
измеряемой разметки есть низкоуровневый `layout_with_measurer`: реализация
`UiMeasurer` получает label/button и доступный размер родителя, возвращает
размер содержимого, а движок добавляет внутренние отступы и оставляет приоритет у
`Points`/`Fill`. Ошибка измерения возвращается вместе с `WidgetId`, а не
теряется в строке.

`ScrollView` — ограниченная вертикальная область с ровно одним `Column`-child.
Задайте viewport через constraint самого `ScrollView`, а content height — через
constraint column. `layout_with_input_state` применяет retained offset из
`UiInputState`; `handle_scroll_input` ограничивает его диапазоном
`0..=max(0, content_h - viewport_h)`. Потомки получают clip viewport: они не
попадают в pointer hit-test вне него; `yuyib-ui-render` передаёт этот clip в
CPU intersection и WGPU scissor; `ApplicationUi::with_text` применяет тот же
`UiLayout::clip` к glyph pass через `TextClipRect`. При overflow input-aware
extract рисует вертикальный thumb (`UiVisualStyle::scroll_thumb`, геометрия
`vertical_scroll_thumb_bounds`) — без drag и inertia. Вложенные `ScrollView`
пересекают clip на layout path. Virtualization пока отсутствует.

Клавиатурная поддержка пока семантическая: нет ввода текста/IME, перевода
раскладки, политики повторов или системной доступности.

`yuyib::input::WinitUiAdapter` — мост Winit: он буферизует курсор, левую
кнопку мыши, колесо мыши, Tab/ShiftTab/Enter/Space и потерю фокуса, затем выдаёт
упорядоченные `UiResponse` на выбранной приложением границе кадра.
`UiDpiPolicy` задаётся явно: физические пиксели либо переданный масштаб
логических пикселей. Для высокоуровневого пути используйте
`ApplicationUi::with_winit_input(adapter, on_response)`: приложение выдаёт
ответы в порядке поступления до пользовательского `on_render`, затем рисует
UI поверх результата. Для собственной политики событий остаётся
`on_window_event`.

Текущий GPU-мост рисует заполненные прямоугольники, внутренние границы и
контур фокуса. `UiClipRect` добавляет одну явную прямоугольную область
отсечения на проход: `extract_draw_list_clipped` и
`extract_draw_list_with_input_clipped` обрезают фон, границы и фокус на CPU,
а затем передают ограниченный WGPU scissor-прямоугольник. Удобный путь —
`UiRenderer::draw_clipped`; `UiInputRenderOptions::with_clip` делает то же
для рисования с вводом. Пустая либо целиком внешняя область не создаёт GPU
команду и не расходует `UiRenderLimits`. Прямой создатель `UiDrawList` может
задать `UiRectangle::clip`; рендерер ограничит его поверхностью до вызова
WGPU, поэтому отрицательные, пустые и внешние значения не приводят к panic.

Это сознательно ещё не scrollbar drag/inertia, иерархия доступности или полный
текстовый input/IME. У прямоугольного моста пока нет скруглений, иконок,
изображений, постоянного объединения вызовов и рендеринга для доступности.
Glyph overlay и scroll thumb в `ApplicationUi` уже уважают scroll viewport.

`UiVisualStyle` добавляет необязательные внутренние границы и контрастный
контур клавиатурного фокуса. Если это нужно, используйте
`extract_draw_list_with_input` или `UiRenderer::draw_with_input`; старые
`extract_draw_list`/`draw` намеренно рисуют только фон для совместимого
явного поведения. Границы и контуры фокуса учитываются в `UiRenderLimits`.

`yuyib::ui_text` — слой ограниченного формирования и измерения текста.
`TextEngine` принимает только явные байты шрифта приложения или один точный
путь и никогда не сканирует системные шрифты. Он использует `cosmic-text` для
глифов в визуальном порядке, диапазонов UTF-8, строк, признаков RTL и метрик
в пределах лимитов шрифта/текста/строк/глифов. `TextLayoutOptions` задаёт
размер, перенос и выравнивание. WGPU-атлас, растеризация и резервные шрифты —
следующие отдельные слои.

Полный API: [формирование текста](../api/yuyib_ui_text/index.html).

`yuyib::ui_text_render` растеризует сформированные идентификаторы глифов через
кэш Swash из `cosmic-text` в ограниченный повторяемый RGBA8-атлас.
`TextRasterizer` возвращает пиксели атласа и упорядоченные UV-`TextQuad`;
пробелы попадают в кэш без квадрата. Байты/источник шрифта обязаны точно
совпадать с источником `TextEngine`, чтобы номера граней не менялись.
`TextGlyphRenderer` — явный WGPU-потребитель: один раз вызовите
`upload_atlas`, обновляйте постоянный атлас того же размера через
`update_atlas`, затем вызывайте `draw` с согласованными `TextDrawList`,
`TextViewport` и необязательным `TextClipRect` внутри области вывода.
`update_and_draw` — удобный путь для нового `TextAtlasFrame`. Он проверяет
лимиты RGBA-байтов/квадов, размер атласа и конечность UV/цветов/геометрии до
записи одного прозрачного прохода. Пустая либо внешняя область отсечения не
создаёт draw-вызов и не требует специальной GPU-заготовки шрифта.

У прямого низкоуровневого текстового прохода по-прежнему нет обязательной
связи с `UiTree`: его можно использовать для HUD, редактора или собственного
рендерера.
Готовый `ApplicationUi::with_text` закрывает подписи и кнопки, а также даёт
лёгкую подсветку при наведении/нажатии и контур клавиатурного фокуса. Вложенная
область отсечения, прокрутка/редактор/IME/accessibility, резервные шрифты и
нестандартный порядок множества текстовых проходов ещё являются отдельными
подсистемами.

Полный API: [растеризация текста](../api/yuyib_ui_text_render/index.html).
